# 연속 드래그와 WASD 이동

2026-09-11. 조작을 두 가지로 바꾼다.

1. 블록 드래그가 **드래그 한 번에 한 칸**에서, 버튼을 뗄 때까지 **일정한 속도로 계속** 미는
   것으로 바뀐다.
2. 플레이어 이동이 **바닥 클릭 → 길찾기**에서 **WASD**로 바뀐다. 그리드 위를 한 칸씩 걷는
   것은 그대로다.

## 0. 결정 표

| 항목 | 이전 | 이후 |
|---|---|---|
| 블록 드래그 | 드래그 한 번에 한 칸. 더 밀려면 놓았다가 다시 잡는다 | 잡은 지점에서 커서를 반 칸 이상 밀어 둔 채로 있으면 막힐 때까지 정속으로 계속 밀린다 |
| 드래그 방향 판정 | 블록의 **현재 위치** 기준 | 누른 지점(`GrabPoint`) 기준의 **조이스틱**. 반 칸 안으로 되돌리면 다음 칸에서 서고, 반대쪽으로 넘기면 방향이 바뀐다 |
| 플레이어 이동 | 바닥 클릭 → A\* 경로 | WASD(화살표 키도 같음). 누르고 있으면 막힐 때까지 정속으로 걷는다 |
| 키 방향 | — | **W = 화면 왼쪽 위.** yaw −135도 카메라에서 W=서, D=남, S=동, A=북 |
| 클릭 이동 | 바닥 클릭·블록 클릭 모두 이동 | **꺼짐.** 코드는 `CLICK-TO-MOVE DISABLED 2026-09-11 (WASD)` 마커와 `#if 0`으로 남긴다 |
| 탑승 | 엘리베이터·열차·에스컬레이터 클릭 | **그대로.** 문 앞까지 자동으로 걸어가는 예약 탑승도 그대로다 |
| 레버 | 휠 둘레로 드래그, 한 번에 90도 | **그대로** |

`bOneStepPerDrag`는 남기되 **기본값이 false**로 바뀐다. 켜면 예전의 "드래그 한 번에 한 칸"이
그대로 돌아온다. 엘리베이터와 회전 장애물은 지금까지처럼 `CanEditChange`로 이 값을 잠근다.

## 1. 왜 이렇게 했나

### 1.1 이음은 누르는 쪽이 아니라 움직이는 쪽이 한다

한 칸에 도착한 프레임을 그냥 끝내고 다음 틱에 컨트롤러가 다시 밀어 주기를 기다리면, 칸마다
한 프레임씩 서게 되어 요청된 "일정한 속도"가 셀 경계마다 눈에 띄게 끊긴다. 그래서 블록과
폰 모두 **자기 Tick 안에서** 다음 칸을 이어 붙이고, 이번 프레임에 쓰고 남은 이동 거리를
그대로 다음 칸으로 이월한다(거리 예산 루프).

컨트롤러와 폰이 하는 일은 "지금 어느 쪽인가"를 매 틱 알려 주는 것뿐이다:
`APuzzleBlock::SetHeldSlideDirection`, `AGridPawn::SetHeldDirection`.

### 1.2 드래그 기준점을 잡은 지점으로 옮긴 이유

블록의 현재 위치에서 재면 블록이 커서를 따라오면서 델타를 도로 0으로 만든다. 계속 밀려면
손을 칸 수만큼 움직여야 하므로 "버튼을 뗄 때까지 쭉"이 성립하지 않는다. 누른 지점에서 재면
커서는 방향을 가리키는 조이스틱이 되고, 손은 가만히 있어도 된다.

### 1.3 방향을 `CanSlide`로 미리 고르는 이유

커서가 가리키는 후보는 둘이다(우세한 축, 그다음 축). 주축이 막혀 벽을 따라 미끄러지는
중이라면, 이어 밀 방향도 그 벽을 따라가야 한다. 슬라이드 중에는 `MinCell`이 이미 목적지
칸이므로 `CanSlide`는 "도착한 뒤에 그쪽으로 더 갈 수 있는가"에 답한다. 그래서 컨트롤러는
후보 중 통과하는 첫 방향을 골라 넘기고, 블록은 도착 즉시 그 방향으로 이어 간다.

### 1.4 이동 키는 길찾기를 거치지 않는다

키가 가리키는 방향이 곧 명령이다. 막혔을 때 돌아가는 길을 찾아 주면 폰을 직접 민다는 감각이
사라진다. `AGridPawn::TryStepHeldDirection`은 옆 칸 하나만 `CanPawnEnter`로 묻고, 막혔으면
기존 `Bump` 연출과 사유를 **한 번만** 낸 뒤 그 자리에 선다.

길찾기 자체는 살아 있다. 탑승 예약(문 앞으로 걸어가기)과 열차 하차 후 이동이 여전히
`RequestMoveToCell`을 쓴다. 이동 키를 누르면 그 예약은 취소된다 -- 플레이어가 조작을 도로
가져갔다는 뜻이기 때문이다.

### 1.5 두 키를 함께 누르면 나중에 누른 쪽이 이긴다

그리드에는 대각선이 없다. 한 축을 임의로 고르면 방금 누른 키가 무시되어 조작이 먹히지 않은
것처럼 보인다. 나중에 누른 쪽을 따르면 손가락을 옮겨 짚는 대로 방향이 바뀌고, 그 키를 떼면
아직 누르고 있는 이전 키로 되돌아간다. `HeldMoveKeys`가 누른 순서를 들고 있다.

### 1.6 화면 기준 방향과 `KeyboardYawOffset`

카메라가 아이소메트릭이라 월드 X·Y축은 화면에서 대각선으로 놓인다. 카메라 정면을 그대로
쓰면 두 축이 정확히 비겨 W가 어느 쪽으로도 읽힐 수 있다. `KeyboardYawOffset`(기본 −45도)이
그 대각선을 한 축으로 돌려 세운다. 키는 화면 방향으로 고정하고, 셀 축으로의 환산은
`AGridPlayerController::ScreenDirToGridDir`이 **매 입력마다 현재 카메라 yaw로** 다시 하므로
카메라 각도를 바꿔도 조작이 따라온다.

## 2. 코드

| 파일 | 변경 |
|---|---|
| `Puzzle/PuzzleBlock.h/.cpp` | `HeldSlideDir` · `SetHeldSlideDirection` · `GetStepsWhileHeld`, `Tick`의 `Sliding`을 거리 예산 루프로, `bOneStepPerDrag` 기본 false |
| `Player/GridPlayerController.h/.cpp` | `EScreenMoveDir`, 이동 액션 4개(W/A/S/D + 화살표), `HeldMoveKeys`, `KeyboardYawOffset`, `ScreenDirToGridDir`, `IsMoveKeyDown`, `UpdateKeyboardMove`, `UpdateDrag` 조이스틱화, 클릭 이동 `#if 0` |
| `Player/GridPawn.h/.cpp` | `HeldDirection` · `SetHeldDirection` · `TryStepHeldDirection` · `StepOnce`, `TickGridStep`을 거리 예산 루프로, `ltts.PawnStep` |
| `Player/GridHUD.cpp` | 안내 문구, 눌린 이동 키 방향 표시 |

입력 오브젝트는 지금까지처럼 C++에서 만든다. IA_/IMC_ 애셋은 없고 `DefaultInput.ini`도
건드리지 않는다. 이동 키 표(`GetMoveKeyBindings`)는 매핑 컨텍스트를 만들 때와 놓친 뗌
이벤트를 걸러낼 때가 같은 표를 본다 -- 두 곳에 따로 적으면 한쪽만 고쳤을 때 키가 눌린 채로
남아 폰이 혼자 걸어간다.

`GrabOffset`(블록 중심 기준의 그랩 오프셋)은 사라졌다. 블록이 커서를 따라다니던 시절에는
잡은 자리를 유지하려고 필요했지만, 이제 커서가 방향만 가리키므로 식에서 상쇄된다.

## 3. 콘솔

| 명령 | 하는 일 |
|---|---|
| `ltts.PawnStep <N\|E\|S\|W>` | 이동 키를 한 번 눌렀다 뗀 것과 같다. 키보드와 같은 함수(`StepOnce` → `TryStepHeldDirection`)를 지난다 |
| `ltts.BlockSlide <이름 일부> <N\|E\|S\|W>` | 기존 명령. 블록을 한 칸 민다 |

PIE 체크리스트 (`Subway_Stage1` 또는 `GreyBoxTest_1`):

- [ ] 블록을 반 칸 이상 끌고 손을 멈춰도, 벽·다른 조각·폰에 막힐 때까지 정속으로 계속 밀린다.
- [ ] 셀 경계에서 멈칫하지 않는다.
- [ ] 커서를 잡은 지점 근처로 되돌리면 다음 칸에서 선다. 반대쪽으로 넘기면 되돌아온다.
- [ ] 버튼을 떼면 가고 있던 칸까지만 가고 선다.
- [ ] 막히면 사유가 한 번만 뜬다. 뗐다 다시 잡지 않아도 다른 쪽으로 이어 밀 수 있다.
- [ ] 주축이 막힌 블록이 벽을 따라 끊김 없이 미끄러진다.
- [ ] 회전판 위에 놓고 떼면 회전이 지금처럼 발동한다(`ReportAtRest`).
- [ ] 엘리베이터도 문 축을 따라 연속으로 밀린다. 타고 있으면 거부된다.
- [ ] W=화면 왼쪽 위, D=오른쪽 위, S=오른쪽 아래, A=왼쪽 아래. 화살표 키도 같다.
- [ ] 키를 누르고 있으면 막힐 때까지 정속으로 걷는다. HUD의 `[holding ...]`이 맞는 축을 가리킨다.
- [ ] 두 키를 누르면 나중에 누른 쪽, 그 키를 떼면 먼저 누른 쪽으로 돌아간다.
- [ ] 막힌 쪽으로 누르면 한 번 부딪히고 선다. 계속 눌러도 다시 흔들리지 않는다.
- [ ] 계단과 경사로를 WASD로 오르내린다.
- [ ] 바닥 클릭·블록 클릭으로는 더 이상 이동하지 않는다.
- [ ] 엘리베이터·열차·에스컬레이터 클릭 탑승과 문 앞 자동 접근은 그대로다.
- [ ] 접근 중에 이동 키를 누르면 예약이 취소되고 폰이 그 방향으로 걷는다.
- [ ] 조각이 움직이는 동안 이동 키는 대기했다가, 멈추면 누른 채로 바로 이어 걷는다.
- [ ] 알트탭 등으로 창이 포커스를 잃었다 돌아와도 폰이 혼자 걸어가지 않는다.
- [ ] `ltts.PawnStep E`, `ltts.BlockSlide <이름> N`이 동작한다.
