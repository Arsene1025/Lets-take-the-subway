2. 클래스별 역할

정보의 소유자는 월드 서브시스템이고, UI 매니저는 소비자입니다. 스테이지가 곧 레벨이므로, 레벨과 수명이 같은 월드 서브시스템에 두면 레벨 전환 때 지워 줄 코드가 필요 없습니다.

왜 GameInstance가 아닌가

  • 현재 구역은 레벨이 바뀌면 사라져야 하는 값입니다. GameInstance에 두면 레벨마다 초기화를 잊지 않아야 합니다.
  • 레벨을 넘어 남아야 하는 값이 생기면 그것만 따로 둡니다. 클리어한 스테이지 목록이나 이어하기 번호가 그 예입니다. 이때는 UGameInstanceSubsystem을 추가하면 되고, 기본 GameInstance에 자동으로 생성되므로 GameInstanceClass 설정도 필요 없습니다.

3. 레벨 설정 방법

  1. 스테이지 정보 액터를 하나 놓습니다.
    Place Actors 창에서 Stage Info를 검색해 레벨 아무 곳에 놓습니다. 위치는 상관없습니다.
    속성값
    Stage Index스테이지 번호. Subway_Stage1이면 1
    Stage NameUI에 보일 이름. 비워도 됨
    Zone Count총 구역 수. 명시를 권장. 0이면 볼륨에서 유도
  2. 구역마다 볼륨을 놓습니다.
    Stage Zone Volume을 놓고 Shape › Box Extent로 크기를 맞춥니다. 에디터에서 청록색 테두리로 보이고 게임에서는 보이지 않습니다.
    속성값
    Zone Index1부터 빈 번호 없이
    Zone NameUI에 보일 구역 이름. 예: 동쪽 대합실
  3. 경계는 셀 경계에 맞춥니다.
    구역은 폰 중심이 박스 경계를 넘는 순간 바뀝니다. 그리드 1칸은 100 cm이고, Box Extent는 절반 크기이므로 2×2칸이면 Extent X, Y가 100입니다.
  4. 높이는 넉넉히 줍니다.
    폰 중심은 바닥에서 50 cm 위에 있습니다. 같은 구역에 계단이나 위층이 있으면 그 높이까지 덮어야 합니다.
  5. ㄱ자처럼 사각형이 아닌 구역은 박스 여러 개로 덮습니다.
    같은 Zone Index를 준 볼륨 여러 개는 하나의 구역으로 취급합니다. 박스끼리 겹쳐도 됩니다.
  6. 플레이해서 로그를 확인합니다.
    출력 로그에서 StageSubsystem으로 필터링하면 시작 판정 결과와 저작 경고가 나옵니다. 자세한 내용은 9절을 보세요.

Collision 카테고리는 일부러 숨겨 두었습니다. 볼륨의 콜리전 설정은 코드가 정하며, 바꾸면 아트 메시와 오버랩이 나거나 감지가 멈춥니다.

4. UI 매니저 연결 (C++)

UI 매니저는 ULocalPlayerSubsystem이라 레벨이 바뀌어도 살아남습니다. 반면 UStageSubsystem은 레벨마다 새로 생깁니다. 그래서 PlayerControllerChanged가 올 때마다 이전 바인딩을 풀고 새로 바인딩하는 것이 핵심입니다.

이 함수는 레벨이 열려 플레이어 컨트롤러가 로컬 플레이어에 붙을 때 엔진이 부릅니다. 이 시점에는 아직 액터들의 BeginPlay 전이라 상태가 비어 있을 수 있습니다. 판정이 끝나면 OnStageStateChanged가 반드시 한 번 오므로 그걸 기다리면 됩니다.

UIManagerSubsystem.h (예시 이름)

#pragma once

#include "CoreMinimal.h"
#include "Subsystems/LocalPlayerSubsystem.h"
#include "Stage/StageTypes.h"
#include "UIManagerSubsystem.generated.h"

class UStageSubsystem;

UCLASS()
class LETSTAKETHESUBWAY_API UUIManagerSubsystem : public ULocalPlayerSubsystem
{
    GENERATED_BODY()

public:
    virtual void PlayerControllerChanged(APlayerController* NewPlayerController) override;
    virtual void Deinitialize() override;

private:
    void BindStage(UStageSubsystem* Stage);
    void UnbindStage();

    // 델리게이트가 Dynamic이므로 핸들러는 UFUNCTION이어야 합니다.
    UFUNCTION()
    void HandleStageStateChanged(const FStageState& State);

    UFUNCTION()
    void HandleStageZoneChanged(int32 PrevZoneIndex, int32 NewZoneIndex);

    // 레벨이 닫히면 사라지는 객체이므로 약참조로 듭니다.
    TWeakObjectPtr<UStageSubsystem> BoundStage;
};

UIManagerSubsystem.cpp

#include "UIManagerSubsystem.h"

#include "Stage/StageSubsystem.h"
#include "GameFramework/PlayerController.h"

void UUIManagerSubsystem::PlayerControllerChanged(APlayerController* NewPlayerController)
{
    Super::PlayerControllerChanged(NewPlayerController);

    // 이전 레벨의 서브시스템에서 먼저 떨어집니다.
    UnbindStage();

    // 새 컨트롤러가 속한 월드의 서브시스템. 메인 메뉴처럼 게임 월드가 아니면 null입니다.
    BindStage(UStageSubsystem::Get(NewPlayerController));
}

void UUIManagerSubsystem::Deinitialize()
{
    UnbindStage();
    Super::Deinitialize();
}

void UUIManagerSubsystem::BindStage(UStageSubsystem* Stage)
{
    if (!Stage)
    {
        return;
    }

    Stage->OnStageStateChanged.AddUniqueDynamic(this, &ThisClass::HandleStageStateChanged);
    Stage->OnStageZoneChanged.AddUniqueDynamic(this, &ThisClass::HandleStageZoneChanged);
    BoundStage = Stage;

    // 이미 판정이 끝난 뒤에 붙었다면 지금 값을 바로 그립니다.
    // 보통은 판정 전이라 여기서는 넘어가고, 곧 OnStageStateChanged가 옵니다.
    if (Stage->IsResolved())
    {
        HandleStageStateChanged(Stage->GetState());
    }
}

void UUIManagerSubsystem::UnbindStage()
{
    if (UStageSubsystem* Stage = BoundStage.Get())
    {
        Stage->OnStageStateChanged.RemoveDynamic(this, &ThisClass::HandleStageStateChanged);
        Stage->OnStageZoneChanged.RemoveDynamic(this, &ThisClass::HandleStageZoneChanged);
    }
    BoundStage.Reset();
}

void UUIManagerSubsystem::HandleStageStateChanged(const FStageState& State)
{
    // 예: "스테이지 1 · 구역 2 / 5"

}

void UUIManagerSubsystem::HandleStageZoneChanged(int32 PrevZoneIndex, int32 NewZoneIndex)
{

    // 레벨 시작 때는 PrevZoneIndex = 0 으로 한 번 옵니다.

델리게이트 두 개 중 무엇을 쓰나. 화면 숫자를 그리는 용도라면 OnStageStateChanged 하나로 충분합니다. 구역이 바뀌는 순간의 연출이 필요할 때만 OnStageZoneChanged를 추가로 받으세요. 둘 다 오는 경우 OnStageZoneChanged가 먼저 오며, 그때 GetState()는 이미 새 값입니다.

Build.cs. 스테이지 시스템 자체는 추가 모듈이 필요 없습니다. UI 매니저에서 위젯을 쓰면 그쪽 작업에서 "UMG", "Slate", "SlateCore"를 LetsTakeTheSubway.Build.cs에 추가해야 합니다.

5. UI 연결 (블루프린트)

위젯 블루프린트나 레벨 블루프린트에서 바로 쓸 수도 있습니다. 월드 서브시스템은 블루프린트에서 Get StageSubsystem 노드로 얻습니다.

  1. Event Construct 또는 BeginPlay에서 Get StageSubsystem을 호출합니다.
  2. 반환값에서 Bind Event to On Stage State Changed를 연결하고, 커스텀 이벤트에서 Break StageState로 값을 꺼냅니다.
  3. 바인딩 직후 Is Resolved가 참이면 Get State 결과로 한 번 직접 갱신합니다.

위젯의 수명이 레벨과 같다면 레벨 전환 시 재바인딩을 신경 쓸 필요가 없습니다. 레벨을 넘어 살아남는 위젯이라면 C++ 예시처럼 컨트롤러가 바뀔 때마다 다시 바인딩해야 합니다.

8. 생명주기와 방송 시점

레벨이 열릴 때의 순서입니다. UI가 붙는 시점이 액터 BeginPlay보다 빠르다는 점이 중요합니다.

  • 월드 초기화UStageSubsystem 생성. 이 시점 등록부는 비어 있음
  • 배치 액터 컴포넌트 초기화볼륨의 오버랩 핸들러 바인딩 (PostInitializeComponents)
  • 플레이어 컨트롤러 스폰UI 매니저의 PlayerControllerChanged 호출. 여기서 바인딩. 상태는 아직 bResolved = false
  • 폰 스폰첫 오버랩이 계산되지만 볼륨이 아직 등록 전이라 신뢰하지 않음
  • 서브시스템 OnWorldBeginPlay판정 예약만 한다. 이 시점에는 액터 BeginPlay 전이라 등록부가 비어 있음
  • 모든 액터 BeginPlayAStageInfo, 볼륨이 서브시스템에 등록. 폰이 셀에 정렬. 컨트롤러가 델리게이트에 바인딩
  • UWorld::OnWorldBeginPlay 방송폰 위치로 시작 구역을 판정하고 저작 오류를 검사한 뒤, 두 델리게이트를 1회 방송. 컨트롤러가 첫 구역 카메라에 즉시 붙음
  • 플레이 중볼륨 오버랩마다 판정, 바뀐 경우에만 방송
  • 레벨 종료월드 정리 중 발생하는 EndOverlap은 무시. 서브시스템이 델리게이트를 비우고 사라짐

수동 확인 목록

  • WASD로 경계를 넘을 때 폰 중심이 넘는 순간 번호가 바뀌는지.
  • 되돌아오면 이전 번호로 돌아가는지.
  • 열차, 에스컬레이터, 엘리베이터로 경계를 넘을 때도 바뀌는지.
  • 볼륨을 놓은 채 Generate Grid를 눌러도 walkable, blocked 수치가 그대로인지.
  • 블록 드래그, 레버, 탈것 클릭이 전과 같은지.
  • PIE를 두 번 연속 실행해도 두 번 모두 판정 로그가 나오는지.

10. 레벨 전환 시 관리 (FAQ)

Q. UPuzzleSubsystem은 스테이지가 넘어갈 때마다 관리해 줘야 하나요? 직접 해야 하나요?

아니요. 따로 관리할 필요가 없고, 직접 할 일도 없습니다.

엔진이 레벨마다 새로 만들고 레벨이 닫힐 때 함께 없앱니다. UStageSubsystem도 같습니다.

근거는 다음과 같습니다.

  • 월드 서브시스템은 월드와 수명이 같습니다. OpenLevel로 레벨을 바꾸면 이전 월드가 파괴되며 그 서브시스템도 정리되고, 새 월드가 만들어질 때 새 인스턴스가 생깁니다. PIE를 껐다 켤 때도 같습니다.
  • 레벨 밖으로 새는 상태가 없습니다. 코드를 확인한 결과 UPuzzleSubsystem에는 static 변수, 타이머, 외부 델리게이트 바인딩, Initialize나 Deinitialize 재정의가 없습니다.
  • 등록부는 액터가 스스로 관리합니다. 블록, 바닥 타일, 장애물, 레버, 구간, 열차가 모두 BeginPlay에서 등록하고 EndPlay에서 해제합니다. 목록도 약참조라 사라진 액터를 붙들지 않습니다.
  • 폰, 컨트롤러 조회도 매번 월드에서 새로 찾습니다. 저장해 두는 포인터가 없습니다.

Q. 그럼 직접 관리가 필요해지는 경우는요?

상황해야 할 일
레벨을 넘어 남아야 하는 데이터 (클리어 기록, 수집품, 이어하기)UGameInstanceSubsystem을 새로 만들어 거기에 둡니다. 월드 서브시스템에 두면 레벨 전환 때 사라집니다
레벨을 넘어 살아남는 객체가 월드 서브시스템에 바인딩UI 매니저처럼 PlayerControllerChanged에서 풀고 다시 바인딩합니다 (4절)
퍼즐 서브시스템에 static 캐시나 타이머를 추가Deinitialize에서 비우거나 해제합니다
퍼즐 조각을 서브레벨 스트리밍으로 넣고 빼기조치 불필요. EndPlay가 호출되어 자동 해제됩니다

Q. 새 스테이지 레벨(예: Subway_Stage2)을 만들면 무엇을 해야 하나요?

  1. Stage Info를 놓고 Stage Index를 2로 합니다.
  2. 구역 볼륨을 1번부터 놓고 Zone Count를 맞춥니다.
  3. 플레이해서 시작 로그에 경고가 없는지 봅니다.

코드나 설정 변경은 필요 없습니다.

11. 구역 카메라 전환

플레이어가 구역을 옮기면 시점이 그 구역의 고정 카메라로 옮겨 갑니다. 순간이동이 아니라 지금 보이는 시점에서 다음 카메라까지 위치, 회전, 직교 폭을 정해진 시간 동안 보간합니다. 보간은 엔진의 SetViewTargetWithBlend가 하고, 호출은 AGridPlayerController가 합니다.

설정 (StageInfo 디테일 패널 › Stage Info › Camera)

속성설명Subway_Stage1 값
Zone Cameras구역 순서대로 카메라 액터. 0번 칸이 구역 1CAM_Isometric1, 2, 3, 4
Camera Blend Time시점이 옮겨 가는 시간(초). 0이면 즉시1.0
Camera Blend Function보간 곡선. Linear는 일정한 속도, EaseInOut은 출발과 도착이 부드러움Linear

카메라 액터의 Auto Activate For Player는 Disabled로 두세요. 켜져 있으면 레벨 시작 때 엔진이 그 카메라를 먼저 잡습니다. 시작 로그에 경고가 나옵니다.

동작 규칙

상황시점

폰을 따라가는 디버그 카메라

예전의 폰 스프링암 카메라는 지우지 않고 기본으로 꺼 두었습니다. 구역 카메라를 배치하지 않은 맵을 볼 때 켜서 씁니다. 켜져 있으면 구역 카메라보다 우선합니다.

  • 플레이 중 켜기: 콘솔에 ltts.PawnCamera 1. 끄면 현재 구역 카메라로 보간해 돌아갑니다. 에디터를 끄기 전까지 다음 PIE에도 유지됩니다.
  • 항상 켜기: AGridPawn::bUsePawnCamera 기본값을 true로 바꿉니다. 코드에서 PAWN CAMERA DISABLED 2026-09-14로 검색하면 관련 지점이 모두 나옵니다.
