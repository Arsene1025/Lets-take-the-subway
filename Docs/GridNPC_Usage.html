행인 스포너 배치 가이드

레벨에 스포너를 놓고 경유 셀만 적으면 행인이 다닌다. 배치 순서, 프로퍼티, 셀 좌표를 구하는 법, 그리고 안 될 때 무엇을 보는지.

대상 AGridNPCSpawner 작성 2026-09-07 동작 원리 Docs/GridNPC_Flow.html
00

먼저 확인할 것

새 클래스가 에디터에 로드돼 있어야 한다. 코드가 추가된 뒤로 에디터를 한 번도 다시 켜지 않았다면 배치 패널에 Grid NPC Spawner가 보이지 않는다. 에디터를 닫고 아래를 실행한 뒤 다시 켠다.

# 에디터를 완전히 닫은 상태에서
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" ^
  LetsTakeTheSubwayEditor Win64 Development ^
  -project="C:\Users\User\Desktop\Lets-take-the-subway\LetsTakeTheSubway.uproject" -waitmutex

레벨에 AGridActor가 하나 있어야 하고, 경유 셀로 쓸 자리는 이미 Generate Grid가 돌아 있어야 한다. 스포너와 행인은 GridTraceIgnore 태그를 달고 있어서 나중에 다시 구워도 셀을 오염시키지 않는다.

01

세 단계로 놓는다

  1. 스포너를 배치한다

    Place Actors 패널에서 Grid NPC Spawner를 끌어다 놓는다. 행인이 나올 자리, 보통 계단 입구나 승강장 끝이다.

    그리드 밖이어도 된다. 셀에 스냅하지 않고, 행인이 스스로 가장 가까운 셀로 걸어 들어온다. 다만 스포너와 그리드 사이는 직선으로 걷기 때문에 그 사이에 벽이 없어야 한다.

    에디터에 보이는 원뿔은 위치 표식일 뿐이고 게임에서는 보이지 않는다.

  2. 경유 셀을 적는다

    디테일 패널의 Waypoints에 셀 좌표를 순서대로 넣는다. 마지막 셀이 목적지이고, 행인은 거기 닿으면 사라진다. 셀 사이는 A*가 알아서 잇는다.

    모퉁이를 돌게 하고 싶으면 모퉁이 셀을 하나 넣으면 된다. 직선 구간을 잘게 쪼갤 필요는 없다. 좌표를 구하는 법은 3절.

  3. 간격과 수를 정하고 저장한다

    Spawn Interval과 Max Alive를 맞춘다. 기본값 4초 · 3명이면 승강장 하나가 적당히 붐빈다.

    월드 파티션 레벨이라 스포너는 새 외부 액터로 저장된다. 툴바의 Save Current Level을 눌러야 파일이 만들어진다. 액터만 저장하는 방법으로는 저장되지 않는다.

03

셀 좌표 구하는 법

경유 셀은 월드 좌표가 아니라 그리드 셀 번호다. 두 가지 방법이 있다.

방법 1 — 그리드 액터에게 물어본다

그리드 액터를 선택하고 Grid | Debug의 Debug Inspect Cell에 셀 번호를 넣으면, 값을 바꾸는 즉시 출력 로그에 그 셀의 상태가 찍힌다. Debug Path Start와 Debug Path Goal을 채우면 두 셀 사이에 길이 있는지도 같이 나온다. 경유 셀을 확정하기 전에 이걸로 확인하는 편이 빠르다.

cell (70,62): type=Walkable reason=None floorZ=-600.0 neighbours=NES- world=(50,3850,-600)
path (70,62) -> (93,44): 41 step(s) in 0.02 ms.

neighbours=NES-에서 서쪽이 비어 있다는 것은 그쪽이 절벽이거나 막혔다는 뜻이다. 위 예에서 서쪽 (69,62)가 바로 승강장 가장자리 틈이다.

방법 2 — 월드 좌표에서 계산한다

뷰포트에서 원하는 지점의 월드 좌표를 읽고 아래로 바꾼다. 셀 크기는 항상 100 cm다.

셀 → 월드 중심   world = 그리드원점 + (셀 + 0.5) × 100
월드 → 셀        셀 = floor((world − 그리드원점) ÷ 100)

GreyBoxTest_1 기준 그리드 원점 = (-7000, -2400, -700)
예: 셀 (93,44) → X = -7000 + 93.5×100 = 2350,  Y = -2400 + 44.5×100 = 2050

Z는 계산하지 않아도 된다. 행인은 각 셀의 바닥 높이를 따라가므로 계단과 경사로가 저절로 처리된다.

경로를 눈으로 확인할 때는 ltts.GridDebug 2를 켜고 ltts.SpawnNPC를 몇 번 두드리는 편이, 간격 설정을 바꿔 PIE를 다시 켜는 것보다 빠르다.

05

안 될 때

증상원인조치
배치 패널에 스포너가 없다 에디터에 새 클래스가 로드되지 않았다. 0절대로 에디터를 닫고 Development 에디터 타깃을 빌드한 뒤 다시 켠다.
아무도 안 나온다 경유 셀이 비었거나 잘못됐다. 또는 Enabled가 꺼졌다. 출력 로그에서 waypoint N is not a walkable cell을 찾는다. 그 번호의 셀을 고친다.
한 명 나오고 끝난다 경유 셀 사이가 끊겨 스포너가 스스로 멈췄다. disabling this spawner 로그의 두 셀 사이를 본다. Debug Path Start/Goal로 재현된다.
태어나자마자 사라진다 스포너 주변 Entry Search Radius 안에 들어갈 셀이 없다. 스포너를 그리드 쪽으로 옮기거나 반경을 키운다.
엉뚱한 쪽에서 그리드로 올라온다 스포너 반대편에 더 가까운 셀이 있다. 스포너를 원하는 진입 지점 바로 옆으로 옮긴다. 진입은 길찾기가 아니라 최근접 선택이다.
행인이 벽을 통과해 들어온다 스포너와 진입 셀 사이를 직선으로 걷는다. 스포너를 그리드 가장자리에 붙인다. 이 구간만은 길찾기를 쓰지 않는다.
행인이 바닥에 묻히거나 뜬다 Height Above Floor가 0이 아니다. 0으로 되돌린다. 키를 바꾸려면 Body Height를 쓴다.
행인 위를 클릭하면 안 움직인다 이런 일은 없어야 한다. 행인은 콜리전이 전혀 없다. 블루프린트 자식에서 콜리전을 켜지 않았는지 본다.
겹쳐도 반투명해지지 않는다 Ghost Material이 비었다. no ghost material 경고를 확인하고 머티리얼을 넣는다.

07

배치 뒤 확인할 것

  • 로그로 확인
  • 스포너 BeginPlay에 경고 없이 N waypoints valid, timer started가 뜬다.
  • 첫 행인이 entering the grid at cell (70,62)를 찍는다.
  • HUD의 NPCs alive가 Max Alive를 넘지 않고, 간격에 맞춰 늘고 준다.
  • Stage clear … reached by GridNPC 같은 줄이 없다.
  • 스포너를 둔 채 Generate Grid를 다시 눌러도 셀 통계가 그대로다.
  • PIE를 껐다 켜기를 두 번 반복해도 오류가 없다.
  • 눈으로 확인
  • 행인이 스포너에서 그리드로 걸어 들어온다. 순간이동하지 않는다.
  • 진행 방향으로 몸을 돌린다. 코가 가는 쪽을 향한다.
  • 플레이어를 행인 경로에 세워 두면 겹치는 동안 반투명해지고 지나가면 되돌아온다.
  • 행인 위를 클릭해도 플레이어가 그 뒤 바닥으로 이동한다.
  • 경유 셀을 퍼즐 블록 위로 잡아도 행인이 통과하고, 블록은 여전히 밀린다.
  • 목적지에 닿으면 사라지고 다음 행인이 나온다.
